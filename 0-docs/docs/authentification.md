# Connexion et authentification

Pour les **utilisateurs** (mobile et web), l’authentification repose sur **JWT**. Lors du login (`POST /api/auth/login` avec identifiant et mot de passe), le backend vérifie le mot de passe avec bcrypt et renvoie un token JWT signé (python-jose, algorithme HS256). Les routes protégées utilisent la dépendance `get_current_user` : elle lit le header `Authorization: Bearer`, décode le token, vérifie la signature et l’expiration, puis charge l’utilisateur en base. En cas de token invalide ou d’utilisateur inexistant, une erreur 401 est renvoyée. Pour le **Raspberry Pi**, l’authentification se fait par **clé API**. Le RPi envoie le header `X-API-Key` (clé partagée définie dans `.env`). Pour les routes appelées par le RPi (par exemple `POST /api/presence` ou le heartbeat), la dépendance `verify_raspberry_pi` compare cette clé au hash stocké en base pour chaque Raspberry Pi et retourne l’instance correspondante, en mettant à jour `is_online` si besoin. En résumé, deux mécanismes coexistent : JWT pour les utilisateurs humains et clé API pour les Raspberry Pi.
