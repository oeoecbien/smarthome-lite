# Règles d’automatisation (IF-THEN)

Les règles sont stockées en base (table `rules`) sous forme de **conditions** (JSON) et d’**actions**, avec une priorité et un indicateur d’activation. Le moteur de règles (`rule_engine.py`) fournit la méthode `evaluate_rules(trigger_event, trigger_data)` : il charge les règles actives, évalue chaque condition (`_evaluate_condition`) et, si elle est vérifiée, exécute l’action (`_execute_action`) via `DeviceService` (changement d’état ou d’intensité). Les **déclencheurs** principaux sont l’enregistrement d’une présence (`POST /api/presence` ou enregistrement après lecture du capteur dans la boucle du `main`) et, selon la configuration, les changements d’état ou d’intensité lorsqu’ils ne sont pas d’origine manuelle. Un endpoint de test (`POST /api/rules/<id>/test`) permet d’exécuter les règles et de voir si une règle donnée a été déclenchée. Les conditions et actions sont validées (par exemple dans `validators.py`) pour garantir la cohérence des données.
