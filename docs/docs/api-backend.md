# API Backend (FastAPI)

Le backend est le point d’entrée unique pour le mobile et le web. Il gère les utilisateurs, les appareils, les règles, l’IA et relaie les commandes vers le Raspberry Pi. Le point d’entrée est défini dans `main.py`. Au démarrage, l’application se connecte à PostgreSQL, crée un utilisateur admin par défaut si nécessaire et charge les modèles IA (classification et régression). Une tâche asynchrone envoie périodiquement un GET vers chaque Raspberry Pi pour mettre à jour son statut « en ligne » en base. Une autre boucle, toutes les trente secondes environ, interroge les capteurs (`GET /api/devices/<node_id>/sensor`), enregistre les présences et luminosités, applique les règles capteur–lampe et le smart dimming. Les routes exposées couvrent l’authentification, les appareils, les événements, les règles, l’IA, le smart dimming, les Raspberry Pi, les mesures de lumière, la présence et l’administration. CORS, rate limiting en production et validation Pydantic sont utilisés pour la sécurité et la cohérence des données. Pour un contrôle manuel, le flux est le suivant : la route device appelle `DeviceService` ; celui-ci envoie une requête HTTP (POST) vers l’URL du Raspberry Pi (`/api/devices/<gpio_pin>/state` ou `/brightness`), met à jour l’appareil en base et enregistre un événement. Ainsi, Mobile/Web, FastAPI, DeviceService et le Raspberry Pi sont enchaînés de manière cohérente.
